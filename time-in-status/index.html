Time in Status, Cycle Time and Lead Time by Eolivion

Getting started

Time in Status, Cycle Time and Lead Time by Eolivion shows how long work items spend in each status, their cycle time and lead time, and whether they meet your SLA goals. Every time it shows can be opened to see the status changes behind it. It runs inside Jira and makes no calls to outside servers.

Set the working calendar (Jira admin)

  1. Go to Settings > Apps > Time in Status, Cycle Time and Lead Time.
  2. Choose Working hours, check the time zone and write the hours for each day, like 09:00-12:00, 13:00-18:00 for a lunch break. Leave a day empty if nobody works on it.
  3. Add holidays, one per line, as YYYY-MM-DD, and choose Save calendar.

Without a calendar, every hour counts. Reports, SLA goals and the gadget can each count working hours only or every hour.

Run a report

  1. Open a project and choose Time in Status in its navigation.
  2. Write the JQL for the work items you want, or keep the one for the whole project. A report reads up to 10,000 work items.
  3. Choose Run report. You'll see the time in each status with the average, median and 85th percentile, and a table with every work item.

Anyone running a report only sees the work items they can open in Jira.

Check any number

Click a time in the work item table to see when the work item entered and left that status, the clock time, and what the working calendar counted. That's how you can tell whether a weekend or a holiday was left out.

Cycle time and lead time

Open Cycle time and lead time and tick where the time starts and where it ends. It counts from the first time a work item enters a start status until it first enters an end status after that. For lead time, start at your first status. The report then shows the median, the 85th percentile, a scatter chart of finished work items and how the times are spread.

Group, sort and save

Group by work type, priority, assignee, sprint or the month the work item was resolved. Click a column to sort by it, and Shift + click another column to sort by both. Give the report a name and choose Save report so anyone in the project can run it again.

CSV with entry and exit times gives every status a work item passed through, with the date and time it entered and left.

SLA goals (project admins)

Choose SLA goals in the report and add a goal:

  • Time in status: the most time a work item should spend in one status, or in several added up.
  • From one status to another: the most time between entering a start status and entering an end status.

A goal can count working hours only and apply to some priorities or work types. Work items turn amber when they reach 80% of the goal and red when they go over it, in the report, in the work item panel and in the gadget.

On each work item

Open a work item and find Time in Status under Apps. It shows the time in each status, the project's SLA goals for that work item, and every status change.

On a dashboard

Add the Time in Status and SLA gadget to a dashboard. In its settings, write the project key (for its statuses and SLA goals), the JQL and, if you want, where cycle time starts and ends. The gadget keeps its last result in your browser for an hour so the dashboard opens quickly, and Update recalculates it.
